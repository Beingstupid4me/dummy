suspicious-account detection, with \texttt{F3924} as the target
variable.

\begin{itemize}
\tightlist
\item
  dataset integrity checks and class imbalance analysis
\item
  missingness, sparsity, and redundancy diagnostics
\item
  feature engineering for wide financial tabular data
\item
  a lightweight modeling sanity check to validate the engineered feature
  set
\end{itemize}

The workflow is designed to be practical for high-dimensional banking
data where many features are sparse, partially observed, or
uninformative.

    \subsection{Feature Engineering
Strategy}\label{feature-engineering-strategy}

For a sparse, high-dimensional banking dataset, the strongest gains
usually come from three layers:

\begin{itemize}
\tightlist
\item
  removing structurally unusable columns
\item
  adding row-level behavioral summaries that capture account-level
  activity patterns
\item
  keeping only columns with information density and non-trivial variance
\end{itemize}

This is intentionally conservative: it reduces noise without overfitting
to a single split.
